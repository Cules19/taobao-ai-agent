# 选物 3.0 运行与源码指南

选物是本地模拟商城的导购工作台。商品、优惠、物流和知识政策均为虚构。现有 SQLite 历史仍可通过同一浏览器读取；旧消息没有来源卡片，只有实际检索过的 3.0 消息才有来源。

## PyCharm 启动

在现有 taobao-ai-agent 项目打开 Terminal，选择 Python 3.11：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m knowledge_index
.\.venv\Scripts\python.exe run_local.py
```

第三条缺 Key 时会隐藏提示输入；默认 DeepSeek 官方 `deepseek-flash`。访问 http://127.0.0.1:8000/。第二条首次下载 BAAI/bge-small-zh-v1.5 的 ONNX 模型和 tokenizer；后续可加 `--offline`，用户查询始终只尝试本地权重。若下载失败，本店五个业务工具仍可用，知识工具会说明资料不可用。代码用 FastEmbed 在 CPU 上运行，嵌入不使用 DeepSeek Key，也不把查询发给外部嵌入服务。

## 索引与引用

`knowledge/documents.json` 包含 24 篇原创中文模拟资料，每篇具有稳定 ID、标题、主题、版本和“选物模拟资料”标签。长文用 LangChain 的递归切分器分段；短文可只有一个块。修改资料时保留原 ID，更新版本，重跑建索引命令。索引原子替换，原资料散列不一致时旧索引不会被使用。应用离线加载缓存模型；更改缓存路径或挂载卷时，索引和权重两者都需要迁移。

独立 JSON 文件保存分块、归一化向量与来源字段。小语料用全量余弦检索，无需运行向量数据库；低于阈值的结果剔除，至多返回三个不同文档。同一轮的卡片由服务器从检索产物去重生成，模型正文不会被解析成来源卡片。历史记录保存当时显示的片段，而不是用最新版覆盖旧回答。相似度不是事实置信度，模型仍可能误解资料；知识工具未找到证据时使用服务器提示，不把该模型的猜测当答案。

## 运行原理

```text
浏览器 → POST /chat → 校验身份与限额 → SQLite 读取历史 / 获取租约
   → LangGraph: load_session → model ─┬→ tools → model（按调用 ID 回填）
                                    └→ finalize → END
   → 成功才保存整轮与收藏 → 返回文本、商品与真实来源 → 前端渲染
```

LangChain `ChatOpenAI.bind_tools` 把六个 `StructuredTool` 的参数结构发给模型。只有模型返回函数调用后，图才按白名单派发。DeepSeek 官方域名走非思考 Chat Completions；工具结果的 `ToolMessage.tool_call_id` 对应原工具请求 ID。图不配置 checkpointer，不重复保存用户数据。每轮最多 4 次模型请求、每批最多 5 个工具，110 秒轮次预算；单次网络请求最多 25 秒并禁重试。预算在节点边界检查，完成后才更新收藏。模型故障、工具执行故障或超限不会写入半轮。业务无结果可作为正常答复保存。

## 配置速查

| 环境变量 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` / `OPENAI_MODEL` / `OPENAI_BASE_URL` | 聊天服务配置，兼容服务商须支持 Chat Completions 工具协议 |
| `SHOP_EMBEDDING_CACHE` | ONNX 权重目录，默认 .shop-state/embeddings；也可将预下载权重与 tokenizer 放入此目录的 model 子目录 |
| `SHOP_EMBEDDING_MODEL_PATH` | 可选：已下载的 Qdrant 同款 ONNX 和 tokenizer 文件目录；用于无法联网下载的环境 |
| `SHOP_KB_INDEX` / `SHOP_KB_MIN_SCORE` | 默认 .shop-state/knowledge.json；余弦阈值默认 0.65 |
| `SHOP_LANGSMITH_TRACING` | 独立追踪开关，默认 false |
| `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT` | LangSmith 凭据及名称，默认项目 select-studio |
| `LANGSMITH_ENDPOINT` / `LANGSMITH_WORKSPACE_ID` | 可选地域 API 与工作区 |
| `SHOP_ENV` / `SHOP_PUBLIC_ORIGIN` / `SHOP_SESSION_SECRET` | 生产模式、HTTPS Origin 和签名密钥 |
| `SHOP_DB_PATH` / `SHOP_RETENTION_DAYS` | SQLite 文件和保留日期 |
| `SHOP_VISITOR_LIMIT` / `SHOP_SITE_LIMIT` / `SHOP_DAILY_LIMIT` | 访客分钟、站点分钟、全站 UTC 日请求限额 |
| `SHOP_DOMAIN` / `SHOP_ACCESS_USER` / `SHOP_ACCESS_PASSWORD_HASH` | Compose 与 Caddy 私有试点入口 |

PyCharm Terminal 设置环境变量之后再启动。切换模型前确认 Key 与地址匹配。Compose 会读取 .env，直接执行 Python 时不会自动加载该文件。密钥只放本地环境或部署密钥管理器。

## LangSmith 与评估

默认没有 LangSmith 外发。启用时同时设置 `SHOP_LANGSMITH_TRACING=true` 和 Key。打开 LangSmith 的 **Tracing Projects → select-studio → shop.turn**，按 metadata 的 `request_id` 对照 API 响应头和本地日志。展开可看模型、路由节点、工具、检索、耗时与失败状态。应用明确关闭框架原始输入输出追踪，另用 SDK 发送白名单事件：节点名称、开始结束时间、固定状态和随机请求 ID。不会把原始对话、检索正文、工具参数、订单号、Cookie、原始异常或 Key 写入追踪内容；鉴权 Key 本身只用于认证 LangSmith 请求。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m evaluate --mode offline --output evaluation-offline.json
.\.venv\Scripts\python.exe -m evaluate --mode live --output evaluation-live.json
```

离线评估使用模型 HTTP 响应桩和固定嵌入；图、工具、索引写入与检索、SQLite 和 HTTP 路由均真实运行。live 需配置聊天模型、构建真实索引，会消耗模型额度；跳过只适用于故障注入的案例，测试模型是否真实选对工具。报告包含通过率、单案例耗时与中位数。报告默认留本地，不自动建 LangSmith 数据集或上传；如组织许可，可在 **Datasets & Experiments** 手动建立仅包含模拟问题的实验集，区分离线和 live 结果。

## 容器与演示

沿用 2.0 运维手册配置域名和访问凭据。构建后先运行 `docker compose run --rm --no-deps app python -m knowledge_index`；模型下载需要出站网络并持久化到 /state。之后 `docker compose up -d --build --wait`。就绪检查仍验证 SQLite；用受认证的 `GET /api/knowledge/status` 检查索引。indexed 代表文件与语料匹配；实际推理需再问一条知识题来验证 ONNX 缓存。

建议问句：① 找 200 元以内的蓝牙耳机，按销量排序；② 第一款有蓝色吗？③ 主动降噪和被动隔音有什么区别？④ 推荐两款 200 元内的耳机，再解释主动降噪；⑤ 179 元耳机能用什么券？⑥ 查 DEMO1001 的物流。展开来源后刷新，从左栏选原对话确认引用仍在。
